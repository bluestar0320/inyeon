# 인연 계산기 (작업용 이름)

남은 시간과 남은 만남을 **횟수**로 계산하는 앱. 알림이 아니라 계산기이고,
죽음의 카운트다운이 아니라 관계와 순간의 유한함을 체감하기 위한 도구입니다.

> 어머니 60세, 예상 수명 80세, 한 달에 1번 만남 → **앞으로 240번**

구현 계획 전문은 [`docs/PLAN.md`](docs/PLAN.md)에 있습니다.
데이터 모델 · 계산 로직 · 화면 구성 · MVP 범위 · 확장 기능 순으로 정리했습니다.

## 무엇이 되나

- **내 정보** — 생년월일(또는 나이)과 국가·성별로 예상 수명을 자동으로 채우고,
  마음에 들지 않으면 직접 조정
- **인연** — 사람을 등록하고 나이 · 예상 수명 · 만나는 빈도를 입력하면 남은 만남 횟수.
  **내 남은 시간과 상대의 남은 시간 중 짧은 쪽**을 기준으로 계산하고, 어느 쪽이
  기준인지 함께 알려준다
- **순간** — 벚꽃, 해외여행, 서핑처럼 반복되는 일의 남은 횟수
- **결혼 계획** — 목표 결혼 나이와 새로운 사람을 만나는 빈도를 넣으면 그때까지의
  기회 횟수. 목표 나이가 이미 지났으면 0번 대신 목표를 다시 잡으라고 알려준다
- **자녀 성장 캘린더** — 자녀 인연에 켜면 성인이 될 때까지 함께 보낼 봄·여름·가을·
  겨울, 여름방학·겨울방학, 생일, 명절, 주말, 저녁 식사 횟수. 미리 만들어 저장하지
  않고 볼 때마다 아이 나이에서 계산하므로 아이가 자라면 숫자도 같이 줄어든다
- **조건 필터** — 기본값을 밀어 넣지 않고 항목마다 직접 세우는 조건.
  지구온난화로 해마다 줄어드는 서핑, 70세까지만 가능한 일, 유학 3년은 빼기 등
- **연도별 추이** — 총합만 들이밀지 않고 필터 적용 전/후를 연도별로 펼쳐 보여준다
- **톤 전환** — 같은 숫자를 담담하게 / 또렷하게
- **공유 카드** — 결과를 1080×1350 이미지로 저장. 휴대폰에서는 공유 시트가 바로 뜨고,
  안 되면 내려받는다. **나이와 예상 수명은 넣지 않는다** — 남은 횟수는 내보일 만하지만
  "어머니 68세, 예상 수명 87.3세"는 남에게 보낼 정보가 아니다
- **접근성** — axe 위반 0건(밝게·어둡게 모두), 키보드만으로 전부 조작 가능, 본문
  건너뛰기 링크, 움직임 줄이기 존중. 테스트로 고정되어 있어 회귀하면 CI가 잡는다

MVP 범위와 의도적으로 뺀 것(계정, 알림, 자동 트래킹)은 `docs/PLAN.md` §5 참고.

## 실행

```bash
npm install
npm run dev      # http://localhost:3000
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` / `npm start` | 프로덕션 빌드·실행 |
| `npm run typecheck` | 타입 검사 |
| `npm test` | 계산 엔진 단위 테스트 (59개) |
| `npm run test:e2e` | 브라우저 시나리오 + 접근성 테스트 (42개) |

단위 테스트는 Node 내장 러너(`node --test`)와 내장 타입 스트리핑으로 `lib/calc.ts`를
그대로 불러 돌립니다. 별도 의존성이 없고 Node 22.18 이상이면 됩니다.

E2E는 Playwright로 **프로덕션 빌드**를 띄워 돌립니다(개발 서버는 서비스 워커를 등록하지
않아 오프라인 테스트가 성립하지 않습니다). 처음 한 번은 브라우저를 받아야 합니다:

```bash
npx playwright install chromium
```

위 네 가지는 `relationship-countdown/` 안이 바뀔 때마다 GitHub Actions에서 자동으로
돕니다(`.github/workflows/relationship-countdown.yml`). E2E가 실패하면 Playwright
리포트가 아티팩트로 남습니다.

## 구조

```
app/            화면 (Next.js App Router, 전부 클라이언트 컴포넌트)
components/     결과 패널, 필터 편집기, 수명 입력 등
lib/
  calc.ts           계산 엔진 — 순수 함수, React 의존성 없음
  types.ts          데이터 모델
  lifeExpectancy.ts 국가별 기대수명 테이블
  store.ts          localStorage 저장소
  tone.ts           톤별 문구
  presets.ts        관계·순간·필터·만남빈도 프리셋
tests/          계산 엔진 단위 테스트
e2e/            브라우저 시나리오 테스트 (Playwright)
public/         PWA 매니페스트 아이콘, 서비스 워커
docs/PLAN.md    구현 계획
```

## 데이터

**서버가 없습니다.** 모든 기록은 브라우저 `localStorage`에만 저장되고 네트워크로
나가지 않습니다. 기기를 옮기려면 설정 화면의 내보내기/불러오기(JSON)를 쓰세요.

## 예상 수명은 어떻게 구하나

WHO Global Health Observatory의 **연령별 생명표**(2021년)를 앱에 내장해 씁니다
(`lib/lifeTable.ts`, 37개국 × 3성별 × 19개 연령 구간). 한국 수치는 통계청(KOSIS)
생명표와 일치합니다.

흔히 말하는 "한국인 평균 수명 83.5세"는 **갓 태어난 사람** 기준입니다. 태어난 사람
전부를 따라가 평균 낸 값이라 어려서 떠난 분들이 이 숫자를 끌어내립니다. 그런데 이미
68세까지 살아온 분은 그 구간을 통과했으므로 그 평균에 해당하지 않습니다.

> 출발선 1만 명의 평균 완주 시간과, 30km 지점 통과자들의 평균 완주 시간은 다릅니다.
> 중간에 포기한 사람이 앞의 평균에는 들어가고 뒤에는 안 들어가니까요.

그래서 나이별 표를 그대로 씁니다. 차이는 작지 않습니다 — 68세를 월 1회 뵙는다면
예전 방식으로는 186번, 생명표로는 **231번**입니다. 자세한 근거와 수치는
[`docs/PLAN.md`](docs/PLAN.md) §3.6에 있습니다.

대만·홍콩은 WHO 회원국이 아니라 실측 표가 없어 일본 표를 조정한 근사치를 쓰며, 화면에서
그 사실을 밝힙니다. 어느 경우든 예상 수명은 직접 바꿀 수 있고, 바꾸면 그 값이 우선합니다.
