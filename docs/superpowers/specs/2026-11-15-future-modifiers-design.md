# 앞으로 남은 만남 보정 — 설계

2026-11-15. 「몇번더」 출시 전 세 번째 항목(작은 것들 → 지나온 만남 어림 → **미래 보정** → 화면 전환).

## 왜

앱의 첫째 목적은 "남은 만남이 생각보다 적다"를 보여 줘서 오늘 연락하게 하는 것이다. 지금은 적어 둔 빈도가 죽을 때까지 그대로 간다고 센다. 실제로는 나이가 들수록, 결혼하고 아이가 생기면서 친구를 덜 본다. 그 줄어듦을 기본으로 반영해 숫자를 더 정직하게(작게) 만든다.

사용자 원칙: "사용자의 행동과 불편함을 최소화 시키자." 기본 감소는 아무것도 안 눌러도 모두에게 적용되고, 칩은 예외(앞으로 바뀔 일)만 다룬다.

## 목표

- 나이에 따른 만남 감소를 기본으로 적용한다(통계 근거, 감소만).
- 칩 세 개로 앞으로 생길 일을 반영한다: 결혼, 아이, 건강.
- 입력 칸을 늘리지 않는다. 칩은 누르기만 한다.

## 하지 않는 것

- 늘어나는 쪽의 나이 곡선(은퇴 뒤 증가)은 쓰지 않는다. 사용자 결정: "2번(감소만)".
- 칩에 시기 입력 칸을 붙이지 않는다. 칩은 늘 **내년부터** 적용한다.
- "이미 결혼했어요" 같은 현재 상태 칩은 없다. 지금 적은 빈도가 이미 현재 상태를 반영하므로, 다시 깎으면 두 번 빼는 것이다.
- 지나온 만남(과거 어림)은 건드리지 않는다.
- AI 호출 없음. 전부 앱 안 계산.

## 실패로 보는 것

- 이미 결혼한 친구가 다시 깎인다.
- 칩과 「조건」 목록이 같은 내용을 따로 들고 있어 어긋난다.
- 부모님이 나이 감소로 깎인다.
- 숫자가 줄었는데 화면에 이유가 없다.

## 근거 값

| 값 | 출처 |
|---|---|
| 대면 교제 시간(분/일, 평균 하루, 남녀 전체), 2024: 10대 28, 20대 20, 30대 18, 40대 19, 50대 23, 60세 이상 29 | KOSIS 생활시간조사 DT_1TS202004, 항목 S711 |
| 결혼 ×0.5, 아이 ×0.5(누적 ×0.25) | 공식 통계 없음. **앱이 정한 값**(사용자 결정) |
| 건강 칩: 친구 ×0.5, 부모님·조부모님 ×2 | 공식 통계 없음. **앱이 정한 값**(사용자 결정, 부모님 배수는 제안 후 승인) |

건강수명(KOSIS DT_2WH23001, 2021 전체 72.45세)은 조사했으나 이번 설계에서는 쓰지 않는다. 건강 칩은 시기 없이 "내년부터"로 정했기 때문이다.

`lib/futureRules.ts`(새 파일)에 위 값을 출처 주석과 함께 둔다. `lib/pastRules.ts`와 같은 방식.

## 고른 방법

검토한 세 가지:

- **A. 칩이 기존 「조건」을 자동 생성** — "n년 뒤부터 ×배수" 조건 종류가 없어 새로 만들어야 하고, 칩과 조건 목록에 같은 내용이 두 번 보여 어긋난다. 나이 감소는 칩이 아니라 결국 따로 처리.
- **B. 칩 상태는 사람에 저장, 계산 때 해마다 곱하기** — 채택.
- **C. 새 조건 종류 + 칩은 켜고 끄는 단추** — 조건 화면에 고칠 칸이 생겨 담백함을 해치고, A의 중복도 남는다.

사용자가 B를 골랐다. 이유: 칩과 사용자 조건이 서로 독립이고, 칩을 안 누른 사람은 나이 감소 말고 아무것도 바뀌지 않는다. 지나온 만남의 관계 칩(`bonds`)과 같은 결.

## 설계

### 데이터

```ts
// lib/types.ts
export type Ahead = "marry" | "child" | "health";
// Person
ahead?: Ahead[];
```

`lib/store.ts`의 `repairPerson`에서 `cleanAhead`로 다듬는다(알려진 값만, 중복 제거, 배열 아니면 undefined). 내보내기/불러오기 파일에도 그대로 실린다.

### 해마다 곱할 값

`countOccurrences`의 `CountInput`에 선택 인자 `yearFactor?: (i: number) => number`를 더한다. i번째 해 조각의 factor에 곱한다(필터와 같은 자리, `MAX_FACTOR` 상한 전). 유한하지 않거나 음수면 1로 본다. 이 인자가 없으면 지금과 똑같이 동작한다.

`computeRelationship`이 `futureFactor(person, profile, now)`로 이 함수를 만든다(`lib/future.ts`, 새 파일):

```
factor(i) = ageFactor(i) × aheadFactor(i)
```

**ageFactor** — 관계가 친구·동료·그 밖(`relOf`가 friend 또는 other)일 때만. parent, grandparent, partner, child, sibling에는 1.
- 기준 나이: 내 나이(`resolveAge(profile)`), 없으면 상대 나이, 둘 다 없으면 1.
- 그해 나이 = 기준 나이 + i + 0.5(조각 한가운데).
- 연령대 값 표(10년 계단): `<20: 28, 20대: 20, 30대: 18, 40대: 19, 50대: 23, 60+: 29`.
- **감소만**: 지금 연령대부터 그해 연령대까지 거친 값 중 가장 작은 값 ÷ 지금 연령대 값. 1을 넘지 않는다.
  - 예: 지금 25세 → 30대부터 18/20 = 0.9, 이후 40대(19)·50대(23)에도 0.9 유지.
  - 예: 지금 15세 → 20대 20/28 ≈ 0.714, 30대부터 18/28 ≈ 0.643.
  - 예: 지금 35세 이상 → 늘 1.

**aheadFactor** — i ≥ 1(내년부터)인 조각에만. 올해 조각(i = 0)은 1. 관계(`relOf`)별 표(사용자 승인):

| 관계 | marry | child | health |
|---|---|---|---|
| friend, other | ×0.5 | ×0.5 | ×0.5 |
| sibling | ×0.5 | ×0.5 | ×0.5 |
| child(자녀) | ×0.5 (독립) | 없음 | ×2 |
| partner(연인·배우자) | 없음 | 없음 | ×2 (곁에서 돌봄) |
| parent, grandparent | 없음 | 없음 | ×2 |

- 여러 칩은 곱한다(친구 marry+child = ×0.25).
- "없음"인 칩은 화면에서 숨기고, 저장 값이 있어도 계산에서 무시한다(관계가 나중에 바뀐 경우).
- 자녀에게 아이 칩이 없는 이유: 손주가 생기면 더 자주 볼 수도 있어 방향을 정할 수 없다.

i = 1 조각이 "지금부터 1~2년 사이"이므로, 내년부터라는 말과 1년 단위 조각이 맞는다(달 단위로 쪼개지 않는다).

상한: 기존 `MAX_FACTOR`(10배)가 그대로 막는다. 사용자 조건과 곱해져도 마찬가지.

### 화면

- **칩 줄**: 사람 편집 화면(`PersonEditor`)의 관계 칩(`BondFields`) 바로 아래, 「앞으로」 한 줄.
  - 문구: 「결혼할 것 같아요」 「아이가 생길 것 같아요」 「건강이 나빠지고 있어요」 — 이미 그런 상태인 사람에게 누르지 않도록 앞일 말투.
  - 관계별로 위 표에서 "없음"인 칩은 숨긴다. 보일 칩이 하나도 없으면 줄 자체를 숨긴다.
  - `aria-pressed`, `min-h-11`(BondFields 칩과 같은 모양). 5개 언어.
- **이유 표시**: 결과 화면(`ResultPanel`)은 지금 `total < baselineTotal`이면 "조건으로 줄었다"는 줄을 보인다. 나이 감소·칩으로 바뀐 것도 여기 걸리므로, 그 줄이 무엇 때문인지 말하도록 고친다.
  - (설계자 결정) 기준은 지금처럼 `baselineTotal`(적은 빈도 그대로 센 값). total이 baseline과 0.5 넘게 다르면 **늘었든 줄었든** 이유 줄을 보인다.
  - (설계자 결정) 원인별 %는 나누지 않는다. 걸린 원인 이름만 적는다: 나이 / 켠 칩 이름 / 직접 건 조건. 그래서 `countOccurrences`는 원인별 합계를 새로 낼 필요가 없다. `computeRelationship`이 어떤 원인이 실제로 1이 아닌 값을 냈는지(예: `causes: { age: boolean; ahead: Ahead[]; filters: boolean }`)만 함께 돌려준다.
  - 나이 감소가 걸리면 짧은 근거 한 줄: 통계청 생활시간조사에서 30대는 20대보다 사람을 덜 만난다는 취지, 사람 말투.
  - 칩이 걸리면 어떤 칩인지.
  - 앱이 정한 값(결혼·아이·건강)은 "통계가 아니라 앱이 정한 어림"이라고 밝힌다.
- 문구는 메모리 규칙대로 사람 말투, 부모님 높임, 끝맺음 다양.

## 빌더에게 맡기는 것

- `ResultPanel` 근거 줄의 정확한 문구와 배치(위 조건 안에서).
- `yearFactor`를 함수로 넘길지 미리 계산한 배열로 넘길지.
- 테스트 구성. 최소한: futureFactor 단위 테스트(연령대 경계, 감소만, 부모님 무시, i=0 무적용), 칩 없는 기존 사람의 총합이 나이 감소 외엔 그대로인지, fuzz에 `ahead` 무작위 값 추가, e2e 칩 켜고 숫자 줄어드는지와 344px 맞춤.

## 기존 기록 영향

`ahead`가 없는 기존 사람도 친구·그 밖이면 **나이 감소가 새로 걸려 숫자가 줄 수 있다**(20대 이하 사용자만). 의도한 동작이다. 데이터 이전은 필요 없다.
