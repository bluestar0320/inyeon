# 사진첩 디자인과 개인정보 동의 — 설계

2026-09-30. 대화에서 ①②③ 순서로 하나씩 승인받은 내용을 옮긴다.

## 왜

지금 화면은 딱딱하다. 인연을 소중하게 느끼게 하는 "사진첩·추억" 분위기로 바꾼다.
함께, 처음 쓰는 사람이 개인정보 안내에 동의한 뒤에만 앱을 쓰게 한다.

작업 순서: ① 동의 화면 → ② 사진 세트 → ③ 사진첩 디자인.
①은 나머지와 얽히지 않고, ③은 ②의 사진이 있어야 입힐 수 있다.

---

## ① 개인정보 동의 화면

### 흐름

- 동의 기록이 없거나 문구 버전이 올라갔으면, 어느 경로로 들어와도 본문 대신
  동의 화면을 보인다(layout의 `<main>` 안에서 가로챈다). 동의하면 원래 화면이 그대로 뜬다.
- 이미 데이터가 있는 기존 사용자도 한 번 동의한다.
- 설정 화면에 「개인정보 안내」 링크 → `/privacy`(같은 문구, 체크 없이 읽기 전용,
  동의한 날짜 표시).

### 문구 (5개 언어, 실제 동작과 정확히 맞게)

1. **무엇을 적나요** — 내 생년월일·성별·국가·생활 습관, 등록한 사람의 이름·관계·나이·만남 빈도.
2. **어디에 두나요** — 이 기기 안에만. 서버도 계정도 없어 운영자를 포함한 누구도 볼 수 없다.
3. **어디에 쓰나요** — 남은 횟수 계산에만. 광고·분석·제3자 제공에 쓰지 않는다.
4. **어떻게 지우나요** — 설정 → 전체 삭제, 또는 앱 삭제 시 즉시 사라진다.
5. **다른 사람의 정보** — 인연으로 적는 정보는 본인만 보는 개인 메모로만 쓴다.
6. **예외** — '의견 보내기'는 내 메일 앱으로 직접 보내는 것. 웹으로 쓸 때 GitHub Pages가
   일반적인 접속 기록(IP 등)을 남긴다.

사실과 다른 약속은 쓰지 않는다. 스토어 배포 전 법률 검토를 권한다(앱 밖의 일).

### 체크

- [필수] 위 내용을 확인했고 동의합니다
- [필수] 만 14세 이상입니다

둘 다 체크해야 「시작하기」가 켜진다.

### 저장

`Settings.consent?: { version: number; at: string }`. `lib/consent.ts`에
`CONSENT_VERSION = 1`과 `needsConsent(settings)`를 둔다. 문구를 바꾸면 버전을 올린다.
불러오기(import)로 들어온 consent는 무시하고 현재 기기의 것을 유지한다 — 남의 백업
파일로 동의를 건너뛰지 않게.

### 테스트

- 단위: `needsConsent` (없음 / 옛 버전 / 현재 버전).
- E2E: 첫 방문 → 동의 화면, 체크 전 단추 비활성, 동의 후 홈. 기존 E2E는 동의된 상태를
  미리 심고 시작한다. 동의 화면도 axe 0건.

## ② 사진 세트

### 장면 (24장)

프리셋 18개(관계 7 + 순간 11)에 한 장씩, 공용 "인생의 순간" 6장.

| mother | 🌷 | 김 오르는 밥상, 앞치마 걸린 부엌 |
| father | 🌳 | 낡은 자전거 뒷자리, 공원 벤치 |
| grandparent | 🫖 | 시골집 툇마루와 찻잔 |
| sibling | 🧩 | 이층침대, 흩어진 퍼즐 |

| child | 🧸 | 크레파스 스케치북, 작은 신발 |
| friend | 🍻 | 포장마차 불빛, 부딪히는 잔 |

톤: 따뜻한 필름 사진, 살짝 바랜 색. **사람 얼굴 없음** — 물건·풍경·뒷모습만.

### 고르는 규칙 (`lib/photos.ts`)

1. `photo` 필드가 있고 알려진 키면 그것.
2. 아니면 `emoji`가 프리셋 이모지면 그 프리셋의 사진.
3. 아니면 공용 6장 중 `id` 해시로 하나(항상 같은 사진).

`Person.photo?: string`, `Moment.photo?: string` — 키 이름만 저장한다. 모르는 키는 3번
규칙으로 떨어진다(망가진 기록이 앱을 멈추지 못하게 하는 기존 원칙). 사용자 실제 사진은
받지 않는다.

### 파일

`public/photos/<key>.webp`, 600×600, 장당 약 40KB, 합계 약 1MB. 기존 프리캐시가
빌드 산출물 전체를 받으므로 오프라인에서도 보인다. 공유 카드에는 넣지 않는다.

### 생성

힉스필드로 24장을 배치 생성한다. **생성 전 잔액·예상 비용을 보여 주고 동의를 받는다.**
마음에 안 드는 장만 다시 만든다. 결과를 600×600 WebP로 줄여 넣는다.

### 테스트

- 단위: 고르는 규칙 1·2·3과 모르는 키.
- 빌드 검사: `PHOTOS`의 모든 키에 파일이 있는지.

## ③ 사진첩 디자인 (시안 C: 한 장씩 크게, 겹친 더미)

### 홈

- 맨 위 "내게 남은 시간" 큰 숫자는 그대로, 바닥만 종이색.
- **인연**: 폴라로이드 더미. 남은 만남 적은 순. 맨 위 사진 아래에 톤 문장과 큰 숫자,
  누르면 상세로.
- **순간**: 같은 더미를 하나 더.
- 자녀 성장·결혼 계획: 지금 카드 구조 유지, 종이 질감만.

### 넘기기 (`components/PhotoStack.tsx`)

- 가로 `scroll-snap`(CSS)으로 스와이프. 라이브러리 없음.
- ‹ › 단추로 키보드·화면 낭독기 조작. 현재 위치를 "2 / 5"로 알린다.
- 뒤쪽 장은 살짝 기울여 겹쳐 보인다. `prefers-reduced-motion`이면 기울기·전환 끔.
- 한 장뿐이면 더미 없이 한 장.

### 목록·상세·편집

- 인연·순간 목록: 목록 유지, 이모지 자리에 작은 폴라로이드 썸네일. 나란히 비교는 그대로.
- 상세: 결과 위에 큰 폴라로이드 한 장.
- 편집: 「사진 바꾸기」 — 24장 그리드에서 선택.

### 전체 톤

- 크림색 종이 바탕(`--page`, `--surface`, `--hero-bg` 등 `globals.css` 토큰만 교체).
- 사진 아래 이름·문장은 명조(시스템 글꼴 목록: "Nanum Myeongjo", "AppleMyungjo",
  "Batang", Georgia, serif). 웹폰트 없음 원칙 유지.
- 폴라로이드는 각지게(`.polaroid` 컴포넌트 클래스), 단추·입력은 더 둥글게.
- 어둡게: "밤의 앨범" — 짙은 갈색 바탕, 같은 폴라로이드.
- 대비는 기존 기준 유지(axe 0건, 양쪽 테마). 상태바 색(`lib/themeColor.ts`)도 새 바탕에 맞춘다.

### 공유 카드

바꾸지 않는다.

### 테스트

- 기존 E2E·axe 통과(양쪽 테마).
- E2E: 더미에서 › 단추로 다음 사람, 사진 누르면 상세, 사진 바꾸기 후 저장·유지.

---

## 하지 않는 것

- 사용자 실제 사진 업로드.
- 공유 카드 디자인 변경.
- 웹폰트 도입.
- 계정·서버(기존 결정 유지).
